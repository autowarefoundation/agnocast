# Claude Code Rules for ROS 2 C++ (Ubuntu 24.04 & Git)

## 🚫 Forbidden Operations

### 1. Build & Dependency Violations
- **No Direct Build Commands**: Never use raw `g++`, `make`, or `cmake` commands. You must use `colcon build`.
- **No Manual Package Installation**: Never use `apt-get` or manual source builds for dependencies. You must use the provided Ansible playbooks.
- **No Dynamic Dependency Pollution**: Do not modify system-wide configurations or libraries outside the targeted ROS 2 workspace or Ansible control.

### 2. Code Enforcement & Modernization Boundaries
- **No Refactoring of Legacy Code**: Do not modify or fix style violations in existing, untouched code blocks. Keep existing code exactly as it is.
- **No Modern C++ Violations**: Do not use C++20 or C++23 features. Stick strictly to the C++17 standard.
- **No Source File Pollution**: Do not commit build artifacts (e.g., `build/`, `install/`, `log/` directories generated by colcon) to Git.

### 3. Testing & Linter Violations
- **No Blind Test Commits**: Never commit new code without running localized unit tests first.
- **No Hardcoded Test Data Paths**: Do not use absolute paths for test assets or fixtures. Use `ament_index_cpp` to locate package resources.
- **No Suppressed Linters**: Do not disable or bypass `ament_lint` checks in `CMakeLists.txt` unless explicitly instructed.

### 4. Git & Environment Restrictions
- **No Pushes**: Never use `git push` or destructive `git reset` on tracked remote branches without explicit permission.
- **No Silent Sudo**: Do not execute commands requiring `sudo` privileges (including Ansible plays that elevate privileges) without asking first.

2. **Secondary Priority**: [Google C++ Style Guide](https://github.io) (Apply this only where the ROS 2 documentation does not specify a rule).

## 🛠️ Required Workflow Practices

### Compilation & Validation
- **Colcon Workspace Execution**: Always source your setup files (`source /opt/ros/jazzy/setup.bash` or workspace `setup.bash`) before running `colcon`.
- **Ansible Check**: Run the appropriate Ansible playbooks whenever dependency configurations are introduced or updated.
- **Scoped Edits**: Ensure your Git diffs contain changes only for the requested features or fixes to avoid altering legacy code style.

### ROS 2 Testing Framework (GTest & Linters)
- **Test Command**: Run package-specific tests using `colcon test --packages-select <package_name>`.
- **Verify Test Results**: Always inspect results with `colcon test-result --all` or check the `log/` directory to ensure zero failures.
- **Linter Compliance**: Ensure all new files pass `ament_lint_auto` macros (including `ament_cmake_uncrustify`, `ament_cmake_cppcheck`, and `ament_cmake_flake8`).
- **GTest Isolation**: Write independent Google Test (`gtest`) cases for new business logic, ensuring nodes use isolated test executors where necessary.
